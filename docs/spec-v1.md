# dropthis v1 — specification

> Governing spec for v1, produced 2026-09-01 from the founding grilling session and six
> Codex review rounds (decisions #42–#64). Committed on the owner's explicit instruction —
> an exception to the no-plan-files rule. **Current code beats this document on conflict**;
> when v1 ships, superseded parts are marked here, not silently edited. The milestone
> checklists in `docs/decisions.md` #44/#58 define "done".

## Problem Statement

An agent (Claude Code, claude.ai, Cursor, an n8n flow, a script) produces a report, a page, a PDF or a folder and has nowhere to put it that gives back a clean, permanent URL under a domain the user owns, with a password, an expiry and no search-engine indexing. Hosted "artifact" features are tied to one vendor's chat UI, unavailable from API-key sessions, Agent SDK, Bedrock/Vertex or non-Claude agents, and put the content on the vendor's domain. Self-hosted publishing tools need a server, a database, a dashboard and a human to operate them. The previous hosted dropthis solved the URL problem but carried a SaaS's worth of accounts, workspaces, invitations, billing and a console that nobody used, and its clients exposed 20 dead tools to every agent.

The operator (a solo developer, and the agencies like them) needs to give a client team of ~10 non-technical people on claude.ai a way to publish, with one isolated instance per client, no Cloudflare account for the client, no ops, and $0 at personal scale.

## Solution

dropthis v1: one Cloudflare Worker + one R2 bucket (+ one KV namespace for OAuth sessions) deployed into the user's own Cloudflare account by `npx dropthis init`, then operated entirely by agents through five drop operations (`publish`, `update`, `get`, `list`, `delete`) and a small admin set (`user add|list|remove`, `config get|set`, `usage`, `prune`, `doctor`), exposed identically as REST, CLI and MCP from one operation registry. Files are the database: one object per entity, direct GETs on the hot path, atomic claims and generation flips via R2 conditional writes. Every drop carries a generated immutable slug (the URL is the identity), a `title`, an agent-owned `meta` JSON blob, expiry with a 7-day grace, an optional password and `noindex` on. An instance is a team: every user key sees every drop; leaving is revoking a key. Browser connectors (claude.ai, Claude desktop) log in by pasting their key into one OAuth page; everything else sends it as a bearer header. Each instance serves its own agent skill at `/_skill.md`.

Done means two milestones (decisions #44, amended by #58):

- **Milestone 1.** On the operator's Cloudflare account: `npx dropthis init --name damjan --domain damjan.dropthis.app --json` → `dropthis connect --client claude-code --instance damjan` → Claude Code lists the `dropthis_*` tools → "publish this report" (a folder) → the URL opens with `X-Robots-Tag` and a 30-day `expires_at` → `get` returns title, settings and files → `list` shows it → `delete` gives 404; plus one `password: "generate"` publish that unlocks in a browser and one single-file PDF drop.
- **Milestone 2.** `npx dropthis init --name byrokko --domain byrokko.dropthis.app`; the operator's agent runs `user add anna` and gets a key once plus a ready-to-send message. A Byrokko claude.ai **Owner** adds the custom connector once (on Team/Enterprise plans only an Owner can add connectors; on individual plans Anna adds it herself). Anna, from the message alone, connects, pastes her key on the dropthis page, publishes a page and opens the URL — the operator watching, not touching. `user remove anna` ends her access in one call, including her live claude.ai session.

v1 is used privately from the repo build (`npx ./packages/dropthis` or a local link). Publishing `dropthis@1.0.0` to npm is a separate, later milestone — the first public release — and carries the release-trust gate (SBOM, provenance, pinned actions).

## User Stories

### Publishing (agent, user scope)

1. As an agent, I want to publish a set of files in one call and get back a URL, so that I can hand the human a link without a multi-step upload dance.
2. As an agent in claude.ai, I want to send text file content inline in the tool call, so that I can publish without a filesystem.
3. As an agent, I want to send binary content as base64 in a clearly separate field, so that the server never has to guess what my bytes are.
4. As an automation (n8n, a script), I want to pass a `url` per file and have the Worker fetch it, so that I do not have to download and re-upload content I already host.
5. As an agent, I want to publish a single PDF, image or spreadsheet, so that it is served directly at its URL with the right content type.
6. As an agent, I want to publish a folder with an `index.html`, so that the URL opens the page.
7. As an agent, I want a folder without `index.html` to get a generated file list, so that the URL is useful without a repair call.
8. As an agent, I want to set a `title` on publish, so that the human and I can find the drop later in `list`.
9. As an agent, I want to store a `meta` JSON object on the drop, so that five days later I can `get(url)` and know what the drop is, where the data came from and which workflow made it.
10. As an agent, I want `password: "generate"` to return a strong password once, so that I can hand the human a ready-to-send message with URL and password.
11. As an agent, I want to set a chosen password of at least 8 characters, so that the human can pick a memorable one when they insist.
12. As an agent, I want `expires` as `"7d"`, a date or `"never"`, so that I do not compute timestamps.
13. As an agent, I want the instance policy's defaults (30 days, noindex on) applied when I say nothing, so that the safe behaviour is the default.
14. As an agent, I want to send an `idempotency_key` with `publish`, so that a retry after a lost response returns the same drop instead of creating a second one.
15. As an agent, I want `publish` to return the full `Drop` object plus the URL, so that one response has everything I report back.
16. As an agent on a CLI, I want stdout to be only the URL on `publish`, so that I can pipe it.
17. As an agent, I want a clear error when a path is invalid (absolute, `..`, backslash, control characters, duplicate, too long), so that I fix the manifest instead of guessing.

### Updating

18. As an agent, I want to replace a drop's files at the same URL in one call, so that the human's link keeps working.
19. As an agent, I want to change only the password, or only the expiry, or only the title, without re-uploading content, so that a settings change is cheap.
20. As an agent, I want to change files and settings in one `update` call, so that I do not need to know which of two verbs to call.
21. As an agent, I want an `update` that repeats the current state to be a no-op, and an `update` with `idempotency_key` to return the same result on retry, so that a timeout cannot make a second generation or a second generated password.
22. As an agent, I want `update({meta: {...}})` to merge at the top level and `null` to delete a key, so that I can record progress without re-sending the whole blob.
23. As an agent, I want `password: null` to remove the password, so that a drop can be opened up.
24. As an agent, I want `update({expires})` to work on a drop that expired less than 7 days ago, so that "the link died, bring it back" is one call.
25. As a visitor, I want a multi-file update to be atomic, so that I never see half-new pages.
26. As an agent, I want a concurrent update by a colleague to fail with a distinct conflict error I can retry, so that neither of us silently loses a change.

### Reading and finding

27. As an agent, I want `get` to accept either the slug or the full URL of this instance, so that I can act on whatever the human pasted.
28. As an agent, I want `get` on a URL from another host to fail with a clear error, so that I never mutate the wrong instance's drop by slug collision.
29. As an agent, I want `get` to return title, settings, `meta`, `created_by`, `state` and the file list with sizes and hashes, so that the drop is its own memory.
30. As an agent, I want `get(..., files: true)` to return text file content inline whether or not the drop has a password, so that pull → edit → `update` needs no local state and no cookie.
31. As an agent, I want binaries and oversized text files listed with an authenticated download URL, so that I can fetch them with my key when I need them.
32. As an agent, I want `list` to return the newest drops first with `url, slug, title, created_by, created, updated, expires_at, noindex, has_password, state`, so that one page answers "what did we publish".
33. As an agent, I want a `q` substring filter over `title` in `list`, so that "the Q4 report from last week" is one call.
34. As an agent, I want cursor pagination on `list` and to know when a page filtered by `q` is empty but more pages exist, so that I keep paging instead of concluding "not found".
35. As an agent, I want `password` never to be returned by `get` or `list`, so that a leaked read cannot leak a secret.

### Deleting and expiry

36. As an agent, I want `delete` to remove the drop, its files and its pointers immediately, so that a wrong publish is gone.
37. As a visitor, I want an expired drop to answer 410 the moment it expires, so that stale reports are not served past their date.
38. As an operator, I want expired drops deleted by a daily cron after the 7-day grace, so that the bucket does not fill with dead previews.
39. As an operator, I want the cron to re-read a drop's metadata before deleting, so that an extended expiry is never deleted because of a stale marker.
40. As an operator, I want a cron that missed a day to catch up on the next run, so that nothing is stranded forever.
41. As an operator, I want abandoned uploads cleaned by an R2 lifecycle rule and orphaned generations by a weekly reconcile, so that garbage never needs a human.
42. As an operator, I want `prune --dry-run` and `usage` to tell me what would go and what is stored, so that I can see the instance without a dashboard.

### Serving

43. As a visitor, I want a password-protected drop to show one unlock form and set a cookie, so that I enter the password once.
44. As a visitor, I want a password change to invalidate old unlock cookies, so that a revoked password really locks the drop.
45. As a visitor, I want every response to carry `X-Robots-Tag: noindex, nofollow` when `noindex` is on, so that search engines stay out, for files too.
46. As a visitor, I want files served with the right content type and `Content-Disposition: inline`, so that a PDF opens in the browser.
47. As a visitor, I want updates and expiry visible on the next request, so that "refresh" shows the truth (no stale browser or edge cache).
48. As an operator, I want a slug never to shadow `/_api`, `/_oauth`, `/_connect` or `/_skill.md`, so that the control plane cannot be hijacked.
49. As a visitor on the `*.workers.dev` hostname of an instance that has a custom domain, I want to be redirected to the canonical URL, so that one drop has one address.

### Keys, users and teams (admin scope)

50. As an operator's agent, I want `user add <label>` to return a key once plus a `connect` object with per-client snippets and a ready-to-send message, so that onboarding a person is one call and one paste.
51. As an operator's agent, I want `user add` with an existing label to fail, so that "anna" always means one person.
52. As an operator's agent, I want `user list` to show labels, ids, scopes and creation dates, never keys, so that I can audit the team.
53. As an operator's agent, I want `user remove <label>` to end that person's access in one call, including every OAuth session behind the key, so that leaving is instant.
54. As a team member's agent, I want to see and edit every drop in the instance, so that a colleague's URL never hits a permission wall.
55. As an operator, I want a `user`-scoped key to see only the five drop tools in MCP, so that a colleague's agent context is not cluttered with admin tools.
56. As an operator, I want the admin key to be an ordinary key record with label `admin`, so that there is one listing, rotation and revocation path for every credential.
57. As an operator, I want keys stored hashed and compared in constant time, and never printed to logs, so that a log leak is not a key leak.

### Connecting (auth)

58. As an agent in Claude Code, Cursor or Codex, I want to send my key as a bearer header over HTTP MCP, so that no browser login is needed.
59. As a person on claude.ai or the Claude desktop app, I want to log in to the instance's connector by pasting my key on one page, so that I never see Cloudflare or a dashboard.
60. As a claude.ai Owner, I want to add the instance as a custom connector once for my whole organisation, so that every member logs in with their own key.
61. As an operator, I want OAuth handled by Cloudflare's provider library with our code limited to the paste-key page, so that we do not maintain an OAuth server.
62. As an operator, I want `/_api/mcp` to accept a bearer header when present and fall back to OAuth only otherwise, so that one endpoint serves both kinds of client.
63. As a security reviewer, I want keys never to appear in URLs, so that they do not land in logs and chat messages.
64. As an agent, I want `dropthis connect --client claude-code` to register the MCP server for me, so that the key never lands in a repo file or a shell history line.

### Installing and operating (CLI, account scope)

65. As an operator's agent, I want `npx dropthis init --name <name> --json` with only `CLOUDFLARE_API_TOKEN` in the environment to derive every resource name from `<name>`, create the bucket and KV, mint the admin key, write its record, deploy with secrets, add the lifecycle rule, attach the domain, run `doctor` and print connect snippets, so that a working instance is one command after three browser steps.
66. As an operator, I want the installer to refuse to guess between several Cloudflare accounts and to name the dashboard permission on a 403, so that a wrong-account deploy cannot happen and a permission error is actionable.
67. As an operator, I want a re-run of `init` to repair missing resources instead of failing and to report `admin_key_status: existing` without re-printing the key, so that reruns are safe.
68. As an operator, I want `--rotate-admin-key` and `--dry-run` to be explicit, so that nothing destructive or secret-revealing happens by accident.
69. As an operator, I want `doctor` to publish, fetch and delete a hello drop and to check MCP `initialize`, so that "deployed" means "works".
70. As an operator's agent, I want `init` to save the instance to `~/.config/dropthis/instances.json` and `--instance <name>` / `DROPTHIS_INSTANCE` to select between my instances, so that I can operate `damjan` and `byrokko` from one machine.
71. As a CI job or n8n flow, I want `DROPTHIS_URL` + `DROPTHIS_KEY` to override any stored instance, so that automation never depends on a home directory.
72. As an agent, I want the CLI never to prompt when stdin is not a terminal or an agent is detected, so that I can never hang on a question.
73. As an agent, I want `--json` to give one deterministic JSON document, `--jsonl` a live event stream where one exists, and documented exit codes (`0/1/2/4`), so that I branch on the result, not on prose.
74. As an agent, I want `dropthis commands --json` to list every command, so that I discover the surface without docs.
75. As an operator, I want a second instance for a client with `npx dropthis init --name client-x`, so that clients are isolated by Worker and bucket, not by a tenant column.
76. As an operator's agent, I want `config get|set` to change the instance's defaults and rules for future publishes and updates, so that a client instance can enforce stricter policy without code and without silently changing existing links.

### Agent onboarding

77. As any agent, I want `https://<host>/_skill.md` to describe this instance's operations, base URL and measured limits, so that one URL onboards me correctly.
78. As an agent, I want errors as `{code, message, remediation, retryable}` with stable codes from a frozen catalogue, so that I act on the code and read the remediation only when I am off-path.
79. As an agent, I want the same `Drop` shape from every operation and surface, so that I parse one thing.
80. As an agent, I want a `429` with `Retry-After` when I write the same drop twice in one second, so that I retry instead of failing.

### Durability

81. As an operator, I want a newer Worker to serve an older drop unchanged (schema field, tolerant readers, lazy read-repair), so that upgrades never need a migration job.
82. As an operator, I want the bucket to be plain S3-compatible files, so that `rclone sync` is a full backup and leaving Cloudflare is a storage swap.

## Implementation Decisions

- **Monorepo, one npm package.** Packages: the deployed Worker; the `dropthis` package (installer, CLI, stdio MCP proxy, bundling the built Worker for `init`); skills; contract tests; a local fake of the Cloudflare management API for installer tests. Bare npm name `dropthis`, republished at 1.0.0 over the archived 0.1.5 at the first public release. `@dropthis/cf` is never published. Commits to `main`; no CI before the first public release.
- **Operation registry.** Every operation defined once (name, input schema, scope, description); REST routes under `/_api/v1`, CLI subcommands and MCP tools (prefixed `dropthis_`) are generated from it in v1; the reference docs generator comes after v1. User scope: `publish`, `update`, `get`, `list`, `delete`. Admin scope: `user add|list|remove`, `config get|set`, `usage`, `prune`, `doctor` — all authenticated with an instance key. `doctor` is a named check registry (decision #29): checks `hello_drop` (publish → fetch → delete), `mcp_initialize`, `policy_readable`, `cron_state`, `canonical_origin`, `pbkdf2_benchmark`, `admin_rotation_clean` — all answerable with an instance key; account-level checks (`lifecycle_rules`, `kv_bound`, `domain_attached`) live in `init`'s reconcile and `init --check`, which need the Cloudflare token; `doctor --list --json` returns `{checks: [{id, description}]}`; `doctor --json` returns `{ok, checks: [{id, status: "pass"|"fail"|"skip", evidence, remediation}]}`. Cloudflare account preflight (token, account pin, R2 subscription, permissions) lives inside `init` and `init --dry-run`, never in `doctor`. Instance lifecycle (`init`, `connect`) lives in the CLI only and uses the Cloudflare token.
- **Key layout (never renamed):**
  - `drops/<id>/meta.json` — authoritative record.
  - `drops/<id>/blobs/<sha256>` — file bodies, content-addressed per drop. A generation is not a directory but a manifest inside `meta.json` (`path → {sha256, size, content_type}`); `<gen>` is the sha256 of that canonical manifest, so identical content yields the same generation id, an unchanged file is never re-uploaded or copied (the Workers R2 binding has no server-side copy), and an update writes only new blobs plus one `meta.json` CAS. Blobs no longer referenced by the current manifest are deleted after the flip (one batched `delete()`) and by the reconcile.
  - `slugs/<slug>` — pointer → id, claimed with `If-None-Match: *` **before** `meta.json` exists (so a collision is found before any other write); used for every lookup. A pointer claimed by a staged publish carries `customMetadata {pending_upload: <upload-id>, expires}`; a pointer whose `meta.json` never appeared is 404 to readers and is removed by the reconcile only when it has no `pending_upload` or that session's `expires` has passed.
  - `list/<inverted-zero-padded-created-ms>-<slug>` — listing pointer; `customMetadata` is string-only and capped at 8,192 bytes, so it carries `id, updated, expires_at (omitted = never), title (≤ 200 bytes UTF-8, the field's limit everywhere), created_by_id, created_by_label (≤ 64 bytes)`; `state` is derived at list time from `expires_at`. R2 lists keys lexicographically, so one `list()` over this prefix is newest-first with a cursor. Written after the metadata commit; a pointer whose `meta.json` is missing is skipped and deleted on read; a `meta.json` whose pointer is missing gets it rewritten by the next `get`/`update` and by the reconcile.
  - `keys/<id>.json` — `{id, label, scope, hash, created}`; `keyhash/<sha256(key)>` — pointer → key id (the auth lookup); `users/<normalized-label>` — pointer → key id, claimed with `If-None-Match: *` so labels are unique. **Label normalization** (one function in the registry, shared by every surface): NFKC → Unicode case fold → trim → runs of whitespace to `-`; the result must match `^[a-z0-9][a-z0-9._-]{0,62}$` else `INVALID_INPUT`; the display label (≤ 64 bytes UTF-8, original form) is stored in the key record and `created_by`. **`user add` order:** write `keys/<id>.json` → `keyhash/` → claim `users/<label>` (on `LABEL_TAKEN`, delete the two records) → return the key; with `idempotency_key` the encrypted result is stored under `requests/` like `publish`, so a lost response is recoverable once. **`user remove` order:** delete `keyhash/` (access ends here) → delete `keys/<id>.json` → delete `users/<label>` last (the label is reusable only after this); every step tolerates 404, so a rerun completes an interrupted removal. The admin key is an ordinary record with label `admin`; there is no separate admin secret.
  - `expiring/<yyyy-mm-dd>/<id>` — hint marker dated `expires_at + grace`.
  - `requests/<sha256(key-id + idempotency_key)>/claim` and `…/result` — two keys, each written once (R2 allows about one write per second per key). The claim `{payload_hash, created}` is put with `If-None-Match: *` **before** any side effect; the result `{slug, response_ciphertext}` is put once at the end, AES-GCM-encrypted with a key derived (HKDF) from `HMAC_SECRET` because it may contain a generated password. A claim older than 60 s with no result is abandoned and may be re-claimed by a retry (unconditional put). Both lifecycle-deleted after 7 days.
  - `uploads/<upload-id>/session.json`, `…/commit`, `…/result` — staged-upload session for the CLI path, three write-once keys (R2 allows one write per second per key): `session.json` `{id, key_id, drop_id, slug?, base_etag?, base_state_hash?, manifest, missing, created, expires}` written at creation (for an update, `base_etag` is the target's `meta.json` ETag at that moment and commit CASes with `If-Match: base_etag`, so an intervening update yields `UPDATE_CONFLICT` and the CLI restarts the session); `commit` `{payload_hash, state_hash, generated_password_ciphertext?}` claimed with `If-None-Match: *` by the first commit; `result` the encrypted `Drop` written once. Lifecycle rule deletes the prefix after 1 day (R2 lifecycle deletion is eventual, not exact). There is no `staging/` prefix: staged PUTs write blobs straight to `drops/<drop_id>/blobs/<sha256>`, where they are unreachable until a manifest references them, so commit copies nothing. Blobs of abandoned sessions are removed by the reconcile (unreferenced and older than 1 day).
  - `system/config.json` — policy and `canonical_url`, `alias_origins`, `instance_name`; `system/prune-state.json` — cron cursors.
  No counters anywhere. `HMAC_SECRET` is the only Worker secret.
- **Instance resource names.** `init --name <name>` normalises the name to `[a-z0-9-]`, 3–30 characters, and derives every resource from it: Worker `dropthis-<name>`, bucket `dropthis-<name>-drops`, KV `dropthis-<name>-oauth`. The names are persisted in `instances.json` and in `system/config.json`; a rerun reconciles by these names; a different instance whose derived names already exist in the account is `NAME_TAKEN`. Two instances on one account therefore never share a resource.
- **`meta.json` fields:** `schema`, `id`, `slug`, `title`, `meta`, `access`, `current_gen`, `manifest` (`path → {sha256, size, content_type}`), `expires_at` (RFC 3339 or `null` for never), `noindex`, `created_by` (`{id, label}` snapshot), `created`, `updated`. Unknown fields ignored, missing defaulted, lazy read-repair on next update.
- **`access.password`:** `{algorithm: "pbkdf2-sha256", iterations, salt, hash, version, nonce}`. `nonce` rotates only when effective access changes — a new password, a generated one, or removal; an `update` whose chosen `password` verifies against the current hash is a no-op and keeps the nonce. The unlock cookie is signed over `{slug, nonce, expires_at}`, so a real password change invalidates every cookie. Cookie attributes: host-only, `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/<slug>/`. Iterations = the highest count that fits the plan's CPU budget, measured once at install and stored in policy.
- **Slug:** generated, 10 characters `a-z0-9`, never starting with `_`, immutable; claimed with `If-None-Match: *`; on the (practically impossible) collision the server generates another. No slug input. Vanity slugs and rename are out.
- **Canonical origin.** `init` stores `canonical_url` (the custom domain when given, else the `*.workers.dev` URL) and `alias_origins` (the `*.workers.dev` URL when a domain exists). Drop URLs, OAuth issuer/resource/discovery documents and `/_skill.md` use the canonical origin. Viewer requests on an alias origin redirect (301) to the canonical one. `get`/`update`/`delete` accept a bare slug or a URL whose origin is canonical or an alias; any other origin fails with `WRONG_INSTANCE`.
- **Writes and idempotency.** The claim fixes the identity, so every retry converges on the same outcome instead of racing. Order for `publish`/`update` with files: (0) resolve content first — decode inline entries, fetch `url` entries, write every new blob under `drops/<id>/blobs/<sha256>` (unreachable until referenced; 1 R2 op per new file, 0 for unchanged; R2 verifies the hash via its `sha256` put option so the Worker never hashes streamed bodies) and compute the resolved manifest; (1) if `idempotency_key` is given, put `requests/<hash>/claim` = `{payload_hash, drop_id, slug, gen, manifest, state_hash, generated_password_ciphertext?, created}` with `If-None-Match: *`, where `state_hash` is the hash of the complete desired `meta.json` (minus `updated`); if the claim already exists: a different `payload_hash` is `409 IDEMPOTENCY_MISMATCH`, an existing `result` is returned decrypted, otherwise the retry **resumes with the claim's identity and manifest** — it `HEAD`s the claim's blobs, re-fetches any missing `url` entry and requires the same hash (`FETCH_FAILED` with remediation "source changed; use a new idempotency_key" otherwise), so two concurrent retries produce one drop; (2) on `publish`, claim `slugs/<slug>` with `If-None-Match: *` (a pointer already holding this drop id counts as claimed; a different id means a real collision → generate another, only possible without a claim); (3) — folded into (0); (4) compare-and-swap `meta.json` (`If-Match: <etag>`; `If-None-Match: *` on create) — if the CAS fails but the stored `meta.json`'s canonical hash equals the claim's `state_hash`, this retry treats it as done (a `current_gen` match alone proves nothing about settings); if it fails on a fresh `publish`, delete the slug claim; (5) write the projections `list/` and `expiring/` — on an expiry change, write the new `expiring/<date>/<id>` marker and delete the previous one (its date is known from the old `meta.json`); on `never`, delete only; (6) put `requests/<hash>/result` once (a retry that finds `meta.json` at `gen` but no `result` writes the result from `meta.json`); (7) delete blobs the new manifest no longer references, one batched `delete()`. Seam 1 includes deployed fault-injection tests (a `DEV_FAULT` header, dev build only) that abort after each step and assert the retry converges. `meta.json` is the only truth. **Equality** for the no-op rule is the canonical JSON (RFC 8785 JCS over values that are already NFC-normalised at input validation — JCS itself does no normalisation; manifest entries sorted by path — pinned by unit fixtures) of `meta.json` excluding `updated`; an `update` that changes nothing returns the current `Drop` without writing. **Projection repair:** `slugs/` is never repaired lazily — it exists before `meta.json` by construction, and a slug pointer whose `meta.json` is missing is 404 and is removed by the reconcile. `list/` and `expiring/` are repaired both ways: an entry without `meta.json` is deleted by whoever reads it; a `meta.json` whose entry is missing or stale (compared on `updated`) is repaired by the next `get`/`update` of that drop and by the reconcile. `password: "generate"` without an idempotency key is documented as non-idempotent. A CAS failure returns `409 UPDATE_CONFLICT` (retryable); R2's per-key write-rate limit returns `429 R2_RATE_LIMIT` with `Retry-After`. No Durable Object.
- **Upload payload:** `files: [{path, text} | {path, base64} | {path, url, sha256?, size?}]` — exactly one of `text`, `base64`, `url` per entry. A `url` entry **with** `sha256` and `size` streams straight into `blobs/<sha256>` with R2 verifying the digest (no Worker CPU, up to `max_file_bytes`); a `url` entry **without** a digest must be hashed by the Worker in-stream, so its size is capped by policy `max_unhashed_bytes` (default 2 MB, same CPU reasoning as inline) and larger undigested URLs are `POLICY_VIOLATION` with remediation "send sha256 and size". The CLI always sends digests; the skill tells agents that automations publishing large files compute the hash. Path rules: relative, forward slashes, NFC, no `..`/`.` segments, no backslash or control characters, ≤ 255 bytes per segment and ≤ 1,024 total, unique after normalisation; violations return `INVALID_PATH`. **URL form** (viewer and `files/{path}` route): each segment is percent-encoded per RFC 3986 (`encodeURIComponent` of the NFC UTF-8 segment) when a URL is generated; on request the path is percent-decoded exactly once per segment, an encoded `/` (`%2F`) or invalid UTF-8 in a segment is `404`, and the decoded, NFC-normalised path is matched against the manifest. Limits, derived from the Free subrequest budget (50 external, 1,000 internal per request; R2 binding calls are internal): ≤ 500 files per call (≤ 500 blob writes + slug claim + 1 CAS + 2 projections + 1 batched delete + 2 idempotency ≈ 507 internal); `url` entries ≤ 20 per call and total fetches including redirects ≤ 45 (redirects followed manually ≤ 3 hops, each re-validated), otherwise `POLICY_VIOLATION`; fetched bytes ≤ `max_file_bytes`; 20 s per fetch; only `http`/`https` on ports 80/443; loopback, link-local, private, cloud-metadata and redirect-to-private targets rejected; the Worker enables `global_fetch_strictly_public`. The single-call ceiling is policy `max_request_bytes`, **default 2 MB, provisional** — inline entries must be JSON-parsed and base64-decoded by the Worker inside the plan's CPU budget (10 ms on Free; parsing, decoding and hashing 25 MB is impossible there); slice 2 measures the true Free-safe value against the deployed `dev` Worker before any skill text is written, and the measured number replaces 2 MB in policy defaults and here; `url` and staged entries are streamed to R2 with R2 verifying the hash, so they cost the Worker almost no CPU and are the way to publish anything large. `/_skill.md` prints the current value and tells agents: text reports inline, files by `url`. Above it the **CLI (the only staged-path client in v1)** uses the staged path below; the same ≤ 500-files rule applies per commit. **Content type** comes from a frozen extension table: `html htm`→`text/html`, `css`→`text/css`, `js mjs`→`text/javascript`, `json map`→`application/json`, `txt`→`text/plain`, `md`→`text/markdown`, `csv`→`text/csv`, `tsv`→`text/tab-separated-values`, `xml`→`application/xml`, `svg`→`image/svg+xml`, `yaml yml`→`application/yaml`, `png`→`image/png`, `jpg jpeg`→`image/jpeg`, `gif`→`image/gif`, `webp`→`image/webp`, `avif`→`image/avif`, `ico`→`image/x-icon`, `pdf`→`application/pdf`, `xlsx`→`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `docx`→`application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `pptx`→`application/vnd.openxmlformats-officedocument.presentationml.presentation`, `zip`→`application/zip`, `mp4`→`video/mp4`, `webm`→`video/webm`, `mp3`→`audio/mpeg`, `wav`→`audio/wav`, `woff`→`font/woff`, `woff2`→`font/woff2`, `ttf`→`font/ttf`; anything else `application/octet-stream`. **Text-typed** = `text/*`, `application/json`, `application/javascript`, `application/xml`, `image/svg+xml` and any `+json`/`+xml` suffix. `text` entries default to `text/plain` unless the extension says otherwise; a `text` entry with a non-text-typed extension is `INVALID_INPUT`.
- **Staged upload path (CLI only in v1):** `POST /_api/v1/uploads` (bearer, user scope) with `{target?: slug, manifest: [{path, size, sha256}]}` — no settings here — allocates the drop id (for a new drop: id and slug are chosen now and the slug is claimed now) and returns `{upload_id, drop_id, missing: [sha256…], put_urls: {sha256: url}, expires}` where each URL is `/_api/v1/uploads/<id>/blobs/<sha256>?exp=<ts>&sig=<hmac>` signed with `HMAC_SECRET` over `{upload_id, sha256, exp}`, valid 1 hour, and is the PUT's only credential; `PUT` streams the body **straight to `drops/<drop_id>/blobs/<sha256>`** (final key, unreachable until referenced; one R2 op), verifies size and sha256 (`HASH_MISMATCH 422`, blob deleted) and is retryable; `POST /_api/v1/uploads/<id>/commit` (bearer, the same key that created the session, else `FORBIDDEN_SCOPE`) carries the settings exactly as `publish`/`update` do — `{title?, meta?, password?, expires?, noindex?}` — and is fenced by the session: the first commit claims `uploads/<id>/commit` (`If-None-Match: *`) with the payload hash, the desired `state_hash` and any generated password (encrypted); a later commit with a different payload is `409 IDEMPOTENCY_MISMATCH`, an identical one resumes or replays `uploads/<id>/result`; it verifies every manifest blob exists (`HEAD`, ≤ 500), then runs steps (4)–(7) of the write order, writes `result` once, and returns the `Drop`; `UPLOAD_EXPIRED 410` after 1 day; a session abandoned before commit leaves only unreferenced blobs, which the reconcile removes (its slug claim is removed with them). Tested in seam 1 (interruption, replay, hash mismatch, expiry, commit conflict) and seam 2 (the CLI choosing the path by size).
- **`update` semantics:** only provided fields change; policy *defaults* apply only on `publish` (an `update` never fills omitted fields from policy), policy *rules* are enforced only on the fields an `update` provides, and an omitted field that no longer complies with a later `config set` is left as it is (grandfathered) — it is rejected only when the caller next sets it; `files` replaces the whole set; `meta` merges top-level with `null` deleting; `password` accepts a string, `"generate"`, or `null`; `expires` accepts `"<n>d"`, an RFC 3339 timestamp, a bare `YYYY-MM-DD` (meaning `T00:00:00Z`) or `"never"`, normalised to `expires_at`, validated against policy `max` and `allow_never`; an `expires_at` in the past is `POLICY_VIOLATION` on every surface, so an `expiring/<date>` marker can never land behind the cron's `oldest_pending_date`.
- **Expiry lifecycle (state machine):**

  | state | condition | viewer | `get` | `update` | `list` | cron |
  |---|---|---|---|---|---|---|
  | `live` | `expires_at` in the future or `null` | serves | 200 | ok | shown | — |
  | `expired_grace` | `now ≥ expires_at`, `now < expires_at + 7d` | 410 | 200 with `state` | ok only with a future `expires` (`EXPIRED_NEEDS_EXPIRES` otherwise) | shown with `state` | — |
  | `expired_final` | `now ≥ expires_at + 7d`, not yet pruned | 410 | `410 EXPIRED_FINAL` | `410 EXPIRED_FINAL` | hidden | deletes |
  | deleted | pruned or `delete` | 404 | `404 NOT_FOUND` | `404 NOT_FOUND` | hidden | — |

  The viewer reads the slug pointer and `meta.json` (both uncached, R2 is strongly consistent) before every response, checks expiry first, then the unlock cookie when `access.password` exists — only after both may it resolve `path → sha256` through the manifest and look up the body in the Cache API under a synthetic `{id, sha256}` key (the cache holds bytes only; `Content-Type`, `Content-Disposition` and every other header are rebuilt from the manifest and the request on each response) that no request URL can address (this amends decision #23: protected bodies may be cached because the cache is behind the check, never in front of it); browsers get `Cache-Control: no-cache, must-revalidate` so updates and expiry are visible on the next request.
- **Cron and prune:** one cron trigger, **hourly** (`0 * * * *`), resumable. `system/prune-state.json` holds `oldest_pending_date`, a per-day cursor and a reconcile cursor and is written **once per invocation, at the end** (one key, one write). Each invocation processes `expiring/<date>/` from `oldest_pending_date` up to today (UTC), re-reads each `meta.json`, deletes only when `expires_at + grace ≤ now`, leaves not-yet-due entries in place, deletes any marker whose date disagrees with the current `meta.json` (a stale marker can never pin the cursor), and **never advances `oldest_pending_date` past a day that is not yet over in UTC** — a day is checkpointed as done only when it is in the past and every marker in it was processed; the budget is **40 R2 operations per invocation** (policy `cron_ops_budget`; derived from the Free plan's 10 ms CPU and 50-subrequest limits with headroom, ≈ 8 expired drops per run, ≈ 190 per day; Paid instances may raise it). A crash before the checkpoint replays the same work next hour harmlessly: every step re-reads `meta.json` and a deleted drop simply reads as 404. Every 7th day the same budget goes to the reconcile: walk `drops/` from the persisted cursor, remove blobs not referenced by the current manifest, slug pointers and `list/`/`expiring/` entries without a `meta.json`, and recreate missing `list/`/`expiring/` entries. `prune --dry-run` and `usage` share one result shape: counts and bytes for `live`, `expired_grace`, `expired_final`, `staging`, `orphan`, plus `incomplete: true` with a cursor when the budget ran out.
- **Responses:** one `Drop` shape (`url, slug, title, created_by, created, updated, expires_at, noindex, has_password, state`; `files[] {path, size, sha256, content_type}` on `get`/`publish`/`update`; `meta` everywhere but `list`). `get(..., files: true)` adds `content` to text-typed files up to 1 MB total in manifest order; any file beyond the budget or binary carries `download_url` instead: `GET /_api/v1/drops/<slug>/files/<encoded-path>` with bearer auth and Range support. `password` only in the response that set it. `list` returns `{drops[], cursor, has_more}`; `q` is a substring match over `title` after NFC normalisation and Unicode case folding, locale-independent; with `q`, a page may be empty while `has_more` is true.
- **REST route table (frozen; the registry generates it, the corpus replays it).** Success responses are the object itself (no envelope), `201` on create, `200` otherwise, `204` on delete; errors are `{error: {code, message, remediation, retryable}}` with the catalogue status. Slugs in paths; the URL form of a target is resolved by the CLI/MCP layer (origin checked against `canonical_url`/`alias_origins`, `WRONG_INSTANCE` otherwise) before the REST call.

  | op | method + path | notes |
  |---|---|---|
  | `publish` | `POST /_api/v1/drops` | body `{files, title?, meta?, password?, expires?, noindex?, idempotency_key?}` |
  | `update` | `PATCH /_api/v1/drops/{slug}` | body: any subset of the same fields |
  | `get` | `GET /_api/v1/drops/{slug}?files=true` | |
  | `list` | `GET /_api/v1/drops?cursor=&limit=&q=` | `{drops, cursor, has_more}` |
  | `delete` | `DELETE /_api/v1/drops/{slug}` | `204` |
  | file download | `GET /_api/v1/drops/{slug}/files/{path}` | bearer, Range |
  | staged upload | `POST /_api/v1/uploads`, `PUT /_api/v1/uploads/{id}/blobs/{sha256}?exp&sig`, `POST /_api/v1/uploads/{id}/commit` | CLI only |
  | `user add/list/remove` | `POST /_api/v1/users`, `GET /_api/v1/users`, `DELETE /_api/v1/users/{label}` | admin |
  | `config get/set` | `GET /_api/v1/config`, `PATCH /_api/v1/config` | admin |
  | `usage` | `GET /_api/v1/usage?cursor=` | admin; returns `incomplete` + `cursor` when the budget ran out |
  | `prune` | `POST /_api/v1/prune` body `{dry_run, cursor?}` | admin; same continuation |
  | `doctor` | `GET /_api/v1/doctor`, `GET /_api/v1/doctor/checks` | admin |
  | MCP | `POST /_api/mcp` (Streamable HTTP) | bearer or OAuth |

- **Error wire shape, one per surface:** REST `{error: {code, message, remediation, retryable}}` with the catalogue status; MCP tool results `isError: true` with the same object as the single JSON content item; CLI `--json` prints the same object to stderr and exits `1` (`4` for `UNAUTHENTICATED`/`FORBIDDEN_SCOPE`).
- **Error catalogue (frozen before implementation; every entry has `code, status, retryable, remediation`):** `INVALID_INPUT 400`, `INVALID_PATH 400`, `POLICY_VIOLATION 400` (expiry above max, never forbidden, password required/too short, file too large, too many files), `UNAUTHENTICATED 401`, `FORBIDDEN_SCOPE 403`, `NOT_FOUND 404`, `WRONG_INSTANCE 404`, `EXPIRED_NEEDS_EXPIRES 409`, `UPDATE_CONFLICT 409 retryable`, `IDEMPOTENCY_MISMATCH 409`, `LABEL_TAKEN 409`, `NAME_TAKEN 409` (CLI), `EXPIRED_FINAL 410`, `UPLOAD_EXPIRED 410`, `PAYLOAD_TOO_LARGE 413`, `HASH_MISMATCH 422`, `FETCH_FAILED 422` (per-file detail: dns, blocked target, redirect limit, timeout, size), `R2_RATE_LIMIT 429 retryable + Retry-After`, `INTERNAL 500 retryable`. No `next` hints on success.
- **Serving matrix:** a single-file drop serves its file at `/<slug>/` and at `/<slug>/<path>`; a folder drop serves `/<slug>/` from `index.html` when present, else the generated list; `/<slug>/<dir>/` serves `<dir>/index.html` when present, else 404; missing paths 404 within a live drop. `Content-Disposition: inline` by default, `?download=1` switches to attachment.
- **Auth:** keys are 32 random bytes, `sha256` stored, `timingSafeEqual` compare; scopes `admin`/`user`; MCP tool list filtered by scope. One key, two presentations: `Authorization: Bearer` (CLI, SDK, CI, `.mcp.json`) and the OAuth paste-your-key page for claude.ai/Claude desktop via `@cloudflare/workers-oauth-provider` with sessions in KV; on `/_api/mcp` header if present else OAuth. Every OAuth token resolves to a key id and is validated against `keys/<id>.json` on each request, so removing the key ends all sessions. Key-in-URL rejected. A spike against a real claude.ai connector runs before OAuth code lands.
- **Admin bootstrap:** `init` mints the admin key, writes `keys/<id>.json`, `keyhash/…` and `users/admin` into the bucket through the Cloudflare R2 API before the first deploy, then deploys with `HMAC_SECRET`. `init` owns the deployed configuration: it renders a per-instance `wrangler.jsonc` with the reconciled bucket **name** and KV namespace **id** filled in (an existing KV namespace cannot be bound by name; Wrangler's id-less auto-provisioning would create a second one) and deploys from that. The id-less `wrangler.jsonc` in the repo is for the Deploy-button path after v1. There is no live-but-unusable window and no separate admin secret. `--rotate-admin-key` is crash-safe, not atomic, and writes `users/admin` **once** per run: write the new `keys/<id>.json` and `keyhash/`; CAS `users/admin` to `{id: <new>, previous: <old>}`; delete the old `keyhash/` pointer (revocation takes effect here); delete the old `keys/<old>.json`. The `previous` field is cleared by a later writer — the next `init` rerun, `doctor`'s `admin_rotation_clean` check, or the next `--rotate-admin-key` — never in the same second. A rerun that finds `previous` set finishes the two deletes first.
- **Team model:** instance = team; all `user` keys see and edit all drops; `created_by` is `{id, label}` attribution. Labels are unique per instance (`users/<normalized-label>` pointer, `LABEL_TAKEN` otherwise); a removed label can be reused and yields a new id. Clients are separate instances; the operator holds every admin key locally.
- **Instance policy** in `system/config.json`, written by `init` with frozen initial values that are safe on the Free plan: `expiry {default: "30d", max: "365d", allow_never: true}`, `password {default: null, required: false}`, `noindex {default: true, forced: false}`, `max_file_bytes: 104857600`, `max_request_bytes: 2097152` (hard ceilings enforced by `config set`: `max_request_bytes` ≤ 64 MB encoded, because the decoded body must fit the 128 MB isolate — and in practice far lower on Free, per the measured CPU budget; `max_file_bytes` ≤ 100 MB, the Worker request-body cap for a streamed staged PUT or `url` fetch; higher values are `POLICY_VIOLATION`), `auto_index: "list"` (the only value in v1; `gallery`/`off` come with the gallery milestone), `pbkdf2_iterations: 5000`, `cron_ops_budget: 40`. No value is measured during `init`. `doctor` includes a `pbkdf2_benchmark` check that times the current iteration count in the deployed Worker and reports the highest count that fits 8 ms; raising it is an explicit `config set pbkdf2_iterations` by the operator's agent, suggested in `init`'s output. **Prospective only:** `config set` changes what future `publish`/`update` calls resolve to; existing drops keep their settings until touched; the response says so.
- **CLI conventions:** bare verbs for the hot path (`init`, `publish`, `update`, `get`, `list`, `delete`, `doctor`, `connect`) and `noun verb` for admin; `CLOUDFLARE_API_TOKEN` (+ `CLOUDFLARE_ACCOUNT_ID`) for `init`, `DROPTHIS_URL` + `DROPTHIS_KEY` for everything else including `doctor`, env beats `~/.config/dropthis/instances.json`, `--instance`/`DROPTHIS_INSTANCE` selects; `connect [--instance x] --client claude-code|cursor|codex|claude-ai --json` applies the per-client registration **with the key in neither argv nor any config file**: Claude Code gets a `headersHelper` (`dropthis auth-header --instance x`, which prints the header from `instances.json`), Cursor and Codex get a reference to the environment variable `DROPTHIS_KEY_<NAME>` (Cursor `${env:…}`, Codex `bearer_token_env_var`) plus the one-line export to add to the shell profile, claude.ai gets the connector URL and the paste-key message; non-interactive when not a TTY or an agent is detected; `--json` is always exactly one document (for `init`, a result object with a `steps[]` array); `--jsonl` streams step events live where a command has them (`init`, `prune`); stdout = result (URL only on `publish`), stderr everything else; exit codes `0` ok, `1` failure, `2` cancelled, `4` auth required; secrets via env/stdin never flags; `@latest` only on the `init` line.
- **Installer:** token-only (never ambient `wrangler login`), account pinned, preflight names dashboard permissions, reconcile bucket and KV by name via the Cloudflare REST API, admin key record written before deploy, `HMAC_SECRET` shipped via `--secrets-file`, lifecycle rules set for `uploads/` (1 day) and `requests/` (7 days), domain attached when the zone is in the account (longest-suffix match; refuse on existing CNAME), `canonical_url`/`alias_origins` written to config, `doctor` run, URL taken from the API never stdout, rerun never re-prints the key, `--rotate-admin-key`, `--dry-run`, `--account-id` explicit. The repo's `wrangler.jsonc` declares bindings by name without ids for the button path; `init` deploys from the rendered per-instance config with the reconciled KV id.
- **Per-instance skill** served at `/_skill.md` with base URL and measured limits substituted; `/_connect` static page with the URL pre-filled.
- **Shared-origin boundary (accepted, decision #28).** All drops of an instance share one origin, so active HTML in one drop can request another drop's path and the browser will attach that path's unlock cookie if the visitor unlocked it. This is documented in `SECURITY.md` as a convenience boundary, not a security one; per-drop origin isolation (a hostname per drop or a sandboxed opaque origin) is a door kept open, not v1. A seam-1 test pins the documented behaviour so a change is deliberate.
- **Reserved prefixes** are literal strings (`/_api`, `/_oauth`, `/_connect`, `/_skill.md`) checked with `startsWith`; generated slugs cannot start with `_`.
- **Hostnames:** `damjan.dropthis.app` (operator's instance), `byrokko.dropthis.app` (client instance), `dev` instance on `*.workers.dev` for tests; all on the operator's existing Cloudflare account and the `dropthis.app` zone.
- **Release phases:** v1 (private, from the repo build) → first public release (`dropthis@1.0.0` on npm with SBOM, provenance, SHA-pinned actions, release manifest, CI running the contract corpus) → later: `upgrade`, button + `claim`, `host_*`, and the rest of the open doors.
- **Doors kept open, empty:** `access` as an object for a later paid unlock; `webhook_url` event bus; vanity slugs; `host_*`; Deploy button + `claim`; `upgrade`/`destroy`; gallery auto-index.
- **Phase order (TDD, size M):** **phase zero — the recorded claude.ai spike** (a throwaway Worker from Cloudflare's remote-MCP template with a custom paste-key authorize page and dynamic client registration, added as a custom connector on a real claude.ai account; if it fails, the auth contract is revised before anything else is built); workspace skeleton + `wrangler.jsonc`; R2 key layout and conditional writes proven against remote R2 (Miniflare is known wrong) including the write-rate and CAS-conflict paths; drop core (publish/update/get/list/delete, expiry states, password, noindex, serving matrix, cron with state); keys + registry → REST, MCP (bearer), CLI; installer `init`/`doctor`/`connect` with the fake management API; OAuth; contract corpus complete and the two milestone scripts run.

## Testing Decisions

- **What a good test is:** it drives a real deployed Worker over HTTP or the real `dropthis` binary as a subprocess and asserts on responses, headers, status codes, exit codes and the bucket-visible outcome — never on internal functions, private module shapes, or Miniflare behaviour. Every row of the expiry state table, every entry of the error catalogue and every line of the serving matrix has a test that would fail if it were removed.
- **Seam 1 — HTTP contract against the deployed `dev` instance (primary).** A golden request/response corpus replayed against `dev` on the operator's account: REST (`/_api/v1`), MCP (`/_api/mcp`, bearer), the viewer (`/<slug>/…`: 200/404/410, unlock form and cookie including invalidation on password change, `X-Robots-Tag`, content types, `Cache-Control`, alias-origin redirect), reserved-prefix collisions, `WRONG_INSTANCE`, idempotency replay and mismatch. Conditional writes (slug claim, `users/` label claim, CAS on `meta.json` with a forced concurrent writer → `UPDATE_CONFLICT`, per-key write rate → `R2_RATE_LIMIT`) are tested here against remote R2, never locally. Expiry states and the cron are driven through a clock override that is compiled only into the `dev` deployment (`DEV_CLOCK` binding absent in production builds; its presence in a non-dev build fails the build) and by invoking the scheduled handler; the missed-day catch-up and the budget-exhausted resume are explicit cases. The harness resets the `dev` bucket directly through the Cloudflare R2 API before every run; there is no public `prune --all`. One fixture per historical `meta.json` schema version is kept forever and must be served unchanged.
- **Seam 2 — the CLI binary as a subprocess.** Against the same `dev` instance for instance commands (`publish` → URL on stdout, `--json` single document, `--jsonl` stream, `instances.json` precedence `env > --instance > default`, non-interactive with stdin closed and `AI_AGENT` set, exit codes, redaction) and, for `init`, against **a local fake of the Cloudflare management API** (token verify, account list with 0/1/2 accounts, R2 subscription missing → `10042`, 403 per permission, partial failure mid-run, rerun repair, `--rotate-admin-key`, `--dry-run`, interrupted deploy). The real `init` runs once per test session against the real account to create `dev`.
- **Seam 3 — pure unit modules (few):** policy resolution (defaults vs rules, prospective application), expiry string parsing and state derivation, slug generation, path validation, manifest hashing and generation ids, schema tolerance of `meta.json` readers, `meta` merge semantics, error catalogue completeness against the registry, MIME table. No I/O, no mocks of R2.
- **Seam 4 — acceptance, manual, recorded.** The claude.ai spike (custom authorize page + dynamic client registration on a real connector) before OAuth code lands, then the two milestone checklists run by the operator's agent against `damjan.dropthis.app` and `byrokko.dropthis.app` with a real claude.ai Owner adding the connector and a real colleague pasting her key; the transcript is the v1 release note. HTTP-only PKCE tests in seam 1 cover the protocol; this seam covers the browser and the connector.
- **Prior art:** none in this repo (no code yet). The corpus format follows the "golden HTTP corpus replayed against a deployed instance" principle in AGENTS.md; the old product's viewer policy tests are read for cases, not copied.

## Out of Scope

Deploy-to-Cloudflare button and `claim`; `upgrade` and `destroy`; `host_*` root-domain drops; gallery auto-index; `llms.txt`; generated reference docs; vanity slugs and slug rename; `webhook_url`; paid unlock / Stripe; ChatGPT connectors (untested, not claimed); attempt rate limiting on passwords; revision history; dashboards or any UI beyond the unlock form, the OAuth paste page and `/_connect`; accounts, workspaces, invitations, roles beyond admin/user; analytics; email/SMS; search index; D1/Durable Objects; Cloudflare Access; compatibility with the archived hosted product's clients; publishing to npm, CI pipelines and release trust (SBOM, provenance) — these belong to the first public release milestone, after v1.
