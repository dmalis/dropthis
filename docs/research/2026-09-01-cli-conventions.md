## 2. Best practices, with the WHY

1. **Bare npm name for the operating CLI; scope only for libraries.** `wrangler`, `vercel`, `supabase`, `sst`, `convex`, `alchemy`, `trigger.dev`, `netlify-cli` are all bare; the one scoped CLI (`@better-auth/cli`) was renamed to bare `auth` after the scoped name installed a generic `cli` bin ([issue #6353](https://github.com/better-auth/better-auth/issues/6353), [1.5 blog](https://better-auth.com/blog/1-5)). WHY: `npx <name>` is the onboarding line an agent copies; scoped names cost a bin-name collision and a longer command. Counter-example: `@railway/cli` (scoped) still exposes bin `railway` — works, but nobody copies it.
2. **`create-*` / `npx <x>@latest init` is a separate package only when it scaffolds someone else's framework.** C3 exists because it templates Astro/Next/etc. and then hands off to wrangler ("C3: To create new projects … Wrangler to build and deploy" [learning path](https://developers.cloudflare.com/learning-paths/workers/get-started/c3-and-wrangler/)); `wrangler init` just delegates to C3. Tools whose install *is* the product (sst, convex, alchemy, trigger.dev, fly) put `init` inside the one CLI. `npm init foo` → `create-foo` is only an npm mechanism ([npm init](https://docs.npmjs.com/cli/v10/commands/npm-init)), not an architectural rule.
3. **Two credentials, two env var names, env beats file.** Every cloud CLI: account token env var (`CLOUDFLARE_API_TOKEN`, `VERCEL_TOKEN`, `SUPABASE_ACCESS_TOKEN`, `FLY_API_TOKEN`, `GH_TOKEN`, `NETLIFY_AUTH_TOKEN`, `RAILWAY_API_TOKEN`) overrides the `login` file; the data-plane key is a distinct name (`TRIGGER_SECRET_KEY`, `CONVEX_DEPLOY_KEY`, `RAILWAY_TOKEN`, Supabase `sb_secret_…`, Fly deploy tokens). WHY: CI holds one, the app holds the other; a mixed-up name is how a deploy token ends up in a runtime, and clig.dev's precedence order (flags > env > project config > user config) makes the override predictable ([clig.dev](https://clig.dev/)).
4. **Mint scoped, expiring data-plane tokens from the CLI, never from a UI.** Fly `fly tokens create deploy -a app -x 48h` / `tokens revoke` ([tokens](https://fly.io/docs/security/tokens/)); Convex deploy keys with a `deployment:deploy` permission. WHY: the agent cannot click a dashboard; self-hosted tools that only mint API keys in the UI (n8n, Coolify, Plausible) are exactly the ones an agent cannot administer. Counter-example: PocketBase `superuser upsert EMAIL PASS` and Coolify `ROOT_USER_*` env seeding are the only self-hosted admin bootstraps that work non-interactively.
5. **Grammar: bare verbs for the 3-4 hot-path actions, `noun verb` for everything else, one convention per tool.** wrangler/vercel/fly/sst all do `deploy` + `r2 bucket create`; gh is strictly noun-verb ("Command = the object, Subcommand = the action" [primer](https://raw.githubusercontent.com/primer/design/main/content/native/cli/foundations.mdx)); clig.dev: "noun verb seems to be more common … Be consistent". WHY: an agent guesses `users add` correctly from having seen `hosts add`; oclif colon topics (`env:set`) are the outlier that only Netlify and n8n use.
6. **stdout is the result, stderr is everything else, and the exit code is the contract.** Vercel: "When deploying, `stdout` is always the Deployment URL … If the exit code is anything other than 0, an error has occurred" ([deploy](https://vercel.com/docs/cli/deploy)); gh publishes 0/1/2/4 ([exit codes](https://cli.github.com/manual/gh_help_exit-codes)); `wrangler whoami --json` "Exits with a non-zero status if not authenticated". WHY: an agent branches on `$?` and pipes stdout; only gh documents a table — most tools leave this UNVERIFIED, which is the gap to close.
7. **`--json` per command as one deterministic document; NDJSON only for streams.** gh `--json <fields>` + `--jq`; better-auth `--json` = "one deterministic JSON document"; Supabase global `--output json`; streams (`vercel logs --json`, `fly logs --json`, `wrangler tail --format json`, `WRANGLER_OUTPUT_FILE_PATH`) are line-delimited. WHY: a single object parses with one `JSON.parse`; NDJSON is for `tail`, never for `create`.
8. **Never prompt when not a TTY or when an agent is detected; `--yes` is the explicit form.** clig.dev: "Only use prompts … if stdin is an interactive terminal"; Vercel: "When the CLI detects that it is running under an agent, non-interactive mode is the default" ([global options](https://vercel.com/docs/cli/global-options)) via [@vercel/detect-agent](https://github.com/vercel/detect-agent) (`AI_AGENT`, `CLAUDECODE`, …); Supabase `--agent auto|yes|no`; Alchemy `ALCHEMY_PLAIN=1` "never prompts"; gh `GH_PROMPT_DISABLED`. WHY: a hung prompt is the #1 agent failure mode; prompts also hide the input contract that `--json` output needs.
9. **Secrets via stdin/file, never flags; never re-reveal.** `wrangler secret put` reads stdin, `secret bulk` a file, `deploy --secrets-file`; Vercel recommends `VERCEL_TOKEN` over `--token` because flags "can be visible in process lists and logs"; clig.dev: "Do not read secrets directly from flags". Coolify API tokens are "shown once". WHY: `ps` and shell history.
10. **Upgrade = one command that keeps CLI and deployed runtime in lockstep, and refuses drift.** trigger.dev `update` pins `@trigger.dev/*` to the CLI and deploy "will automatically fail during CI on any version mismatches"; better-auth `upgrade` pins the lib to the CLI; sst/fly/pocketbase self-update; Plausible/Coolify run migrations at boot. WHY: a version-skewed installer vs Worker is the self-hosted bug class; use `@latest` only for the one-shot `init` line, pin in `devDependencies` after (npm caches stale npx versions, [npm/cli#5262](https://github.com/npm/cli/issues/5262)).
11. **MCP ships with the product and reuses the CLI's credential.** Railway bundled MCP into the CLI (`railway mcp` reuses `railway login`); trigger.dev `install-mcp`; convex `mcp start` with `CONVEX_DEPLOY_KEY`; fly `mcp server` with `FLY_API_TOKEN`; remote servers (Cloudflare, Vercel, GitHub, Supabase, n8n) do OAuth for connector clients plus a bearer-token path for CI. WHY: two credential stores = two rotation paths; connector UIs (claude.ai) cannot send headers, hence OAuth, but every one keeps the bearer path for automation.

## 3. One package or two, for an agent-first tool?

**One npm package, one bin, with lifecycle commands (`init`, `upgrade`, `destroy`, `doctor`, `claim`) as subcommands** — the pattern of sst, convex, alchemy, trigger.dev, flyctl, pocketbase and railway (which even folded its MCP server into the CLI). Reasons that hold for an agent caller: (a) one `npx <name>` line to learn, no version skew between installer and client (trigger.dev/better-auth needed an `update` command precisely because they have two); (b) `doctor` needs both credentials anyway (account token to inspect, instance key to publish a hello drop); (c) the split is enforced by *which credential the subcommand reads* — `RAILWAY_TOKEN` vs `RAILWAY_API_TOKEN`, `TRIGGER_ACCESS_TOKEN` vs `TRIGGER_SECRET_KEY` — not by package boundary.
**Counter-examples and why they do not apply:** C3/wrangler split because C3 templates third-party frameworks and is throw-away; better-auth/trigger.dev split CLI from a *runtime library* that ships to production (Prisma's devDependency-vs-dependency argument, [prisma cli](https://www.prisma.io/docs/orm/v6/tools/prisma-cli)); Coolify's separate Go CLI exists because the server is a Docker/PHP app, not a Node package. dropthis has no framework templating and no runtime library that users import, so none of the three reasons apply. Keep the MCP transport inside the same package (`<name> mcp` stdio proxy, like Railway/Fly/Convex) and let the Worker's `/_api/mcp` be the remote OAuth path.
